# 会议分析-阿里云语音识别集成 修改总结

## 需求概述
将会议分析功能从本地Whisper模型切换到阿里云通义千问语音识别服务,实现以下目标:
1. 使用阿里云DashScope API进行语音转文字
2. 上传音频文件后生成公网链接供阿里云调用
3. 实现轮询查询机制,在后台任务中体现进度
4. 注释本地Whisper模型相关代码
5. 在侧边栏添加语音识别配置入口

### 2. 后端API集成 (`backend/routers/meetings.py`)

#### 2.1 注释本地Whisper模型代码
- 将所有Whisper相关代码注释,保留用于紧急回退
- 包括模型加载、转录函数等

#### 2.2 新增阿里云API函数

**`upload_audio_to_public_url(audio_path: str) -> str`**
- 生成音频文件的公网访问URL
- 使用FastAPI静态文件服务提供访问
- 需要配置`settings.BASE_URL`为服务器公网地址

**`submit_dashscope_asr_task(audio_url: str) -> str`**
- 提交ASR转写任务到阿里云
- 返回task_id用于后续查询
- 支持自定义模型和参数

**`query_dashscope_asr_task(task_id: str) -> dict`**
- 查询ASR任务状态和结果
- 返回完整的任务信息

**`poll_dashscope_asr_result(task_id: str, max_wait_seconds: int) -> list`**
- 轮询查询ASR任务直到完成或超时
- 返回Whisper格式兼容的segments列表
- 默认最多等待1小时

## 技术要点

### 1. 阿里云API调用流程

```
1. 上传音频 → 生成公网URL
2. 提交任务 → 获取task_id
3. 轮询查询 → 检查任务状态
4. 解析结果 → 转换为统一格式
```

### 2. 轮询机制

- 每5秒查询一次任务状态
- 最多等待1小时(可配置)
- 实时更新后台任务进度(30%-70%)
- 支持PENDING、RUNNING、SUCCEEDED、FAILED状态

### 3. 数据格式转换

阿里云返回格式:
```json
{
  "transcripts": [{
    "sentences": [{
      "begin_time": 1000,  // 毫秒
      "end_time": 2000,
      "text": "转录文本"
    }]
  }]
}
```

转换为Whisper格式:
```python
{
  "start": 1.0,  // 秒
  "end": 2.0,
  "text": "转录文本"
}
```

### 4. 后台任务进度体现

```python
# 音频提取: 0-10%
# URL生成: 10-20%
# 任务提交: 20-30%
# ASR转录: 30-70% (轮询期间动态更新)
# 转录完成: 70-90%
# 任务完成: 90-100%
```

## 优势对比

### 本地Whisper模型
- ❌ 需要下载大模型文件
- ❌ 占用服务器CPU/GPU资源
- ❌ 转录速度较慢
- ✅ 无需外部API
- ✅ 数据不出服务器

### 阿里云通义千问
- ✅ 无需本地模型
- ✅ 转录速度快
- ✅ 准确率高
- ✅ 支持长音频(最长12小时)
- ✅ 自动标点、时间戳
- ❌ 需要API Key
- ❌ 需要公网访问
- ❌ 按量计费

## 注意事项

1. **公网访问**: 确保`BASE_URL`配置正确,阿里云需要能访问音频文件
2. **API额度**: 注意阿里云API调用额度和计费
3. **音频格式**: 支持mp3、wav、m4a等常见格式
4. **文件大小**: 长音频模型最大2GB,短音频模型最大10MB
5. **超时处理**: 默认最多等待1小时,可根据需要调整
