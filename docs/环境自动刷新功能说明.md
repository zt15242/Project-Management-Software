# 环境自动刷新功能说明

## 功能概述

为了防止环境配置的 Cookie 失效，系统实现了自动刷新机制，每 2 小时自动重新登录所有激活的环境配置。

## 实现方式

### 1. 定时任务服务

**文件位置**: `backend/services/environment_refresh_service.py`

**核心功能**:
- 使用 APScheduler 实现定时任务调度
- 每 2 小时自动执行一次刷新任务
- 并发刷新多个环境（最多同时 3 个，避免过多 Selenium 实例）
- 自动更新环境的 `cookies`、`last_login_at`、`last_login_status` 字段

**关键类**:
```python
class EnvironmentRefreshService:
    - refresh_all_environments(): 刷新所有激活的环境
    - refresh_environment_login(environment): 刷新单个环境
    - start(): 启动定时任务
    - stop(): 停止定时任务
```

### 2. 启动集成

**文件位置**: `backend/main.py`

在应用启动时自动启动定时任务服务：
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动时
    await connect_to_mongo()
    
    # 启动环境刷新定时任务
    refresh_service = get_refresh_service()
    refresh_service.start()
    
    yield
    
    # 关闭时
    refresh_service.stop()
    await close_mongo_connection()
```

### 3. 手动刷新接口

**接口**: `POST /api/environments/refresh-all`

**权限**: 仅管理员

**功能**: 手动触发刷新所有环境的登录状态

**响应示例**:
```json
{
  "message": "环境刷新任务已启动，请稍后查看各环境的登录状态",
  "status": "started"
}
```

## 刷新逻辑

### 刷新条件
- 环境配置的 `is_active` 字段为 `true`
- 自动每 2 小时执行一次

### 刷新流程
1. 查询所有激活的环境配置
2. 对每个环境调用 Selenium 自动登录脚本
3. 获取新的 Cookie
4. 更新数据库中的环境配置：
   - `cookies`: 新的 Cookie 列表
   - `last_login_at`: 最后登录时间
   - `last_login_status`: 登录状态（success/failed）
   - `updated_at`: 更新时间

### 并发控制
- 最多同时刷新 3 个环境
- 避免创建过多 Selenium 浏览器实例
- 每个环境登录超时时间：60 秒

## 使用说明

### 1. 自动刷新
- 系统启动后自动开始定时刷新
- 无需手动干预
- 每 2 小时自动执行一次

### 2. 手动刷新
如需立即刷新所有环境：
1. 使用管理员账号登录
2. 调用接口：`POST /api/environments/refresh-all`
3. 查看后端日志确认刷新结果

### 3. 查看刷新状态
在环境配置列表中查看：
- `last_login_at`: 最后登录时间
- `last_login_status`: 登录状态
  - `success`: 登录成功
  - `failed`: 登录失败

## 注意事项

1. **依赖 Selenium**: 刷新功能依赖 `selenium_login.py` 脚本，确保该脚本存在且可执行

2. **浏览器驱动**: 确保系统已安装 Chrome 浏览器和对应的 ChromeDriver

3. **网络环境**: 刷新任务需要访问远程环境，确保网络连接正常

4. **登录失败处理**: 如果某个环境登录失败，不会影响其他环境的刷新，失败信息会记录在日志中

5. **性能影响**: 刷新任务在后台异步执行，不会阻塞主应用

## 故障排查

### 问题：定时任务未启动
- 检查后端启动日志，确认是否有 `[启动] 环境自动刷新服务已启动` 消息
- 检查 APScheduler 是否正确安装：`pip list | grep APScheduler`

### 问题：刷新失败
- 查看后端日志中的错误信息
- 检查 `selenium_login.py` 脚本是否存在
- 检查环境配置的 URL、用户名、密码是否正确
- 手动测试单个环境的登录功能

### 问题：Cookie 仍然失效
- 检查刷新间隔是否足够（默认 2 小时）
- 某些系统的 Cookie 有效期可能小于 2 小时，可以调整刷新间隔
- 修改 `environment_refresh_service.py` 中的 `IntervalTrigger(hours=2)` 参数

## 配置调整

### 修改刷新间隔
编辑 `backend/services/environment_refresh_service.py`：

```python
# 修改为每 1 小时刷新一次
self.scheduler.add_job(
    self.refresh_all_environments,
    trigger=IntervalTrigger(hours=1),  # 改为 1
    ...
)
```

### 修改并发数量
编辑 `backend/services/environment_refresh_service.py`：

```python
# 修改最大并发数
max_concurrent = 5  # 改为 5（默认为 3）
```

### 修改登录超时时间
编辑 `backend/services/environment_refresh_service.py`：

```python
result = subprocess.run(
    cmd,
    capture_output=True,
    timeout=120,  # 改为 120 秒（默认 60 秒）
)
```

## 技术细节

- **调度器**: APScheduler AsyncIOScheduler
- **触发器**: IntervalTrigger（间隔触发）
- **数据库**: MongoDB（独立连接，避免共享连接池问题）
- **登录方式**: Selenium WebDriver（通过 subprocess 调用独立脚本）
- **并发控制**: asyncio.gather + 批次处理
