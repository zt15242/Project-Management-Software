# ⚡ Docker 构建加速指南

## 问题：构建速度太慢

### 典型症状
```
=> ERROR [backend 3/10] RUN apt-get update && apt-get install...  236.2s
=> CANCELED [frontend builder 6/8] RUN npm install...             209.9s
```

**原因**：
- ❌ 从国外 Docker Hub 下载镜像慢
- ❌ Debian/Ubuntu apt 源在国外
- ❌ npm 官方源在国外
- ❌ Chrome 下载源在国外

---

## ✅ 已优化的解决方案

### 1. Debian APT 镜像源加速

**已在 Dockerfile.backend 中配置**：
```dockerfile
# 使用阿里云 Debian 镜像源
RUN echo "deb https://mirrors.aliyun.com/debian/ bullseye main contrib non-free" > /etc/apt/sources.list && \
    echo "deb https://mirrors.aliyun.com/debian/ bullseye-updates main contrib non-free" >> /etc/apt/sources.list && \
    echo "deb https://mirrors.aliyun.com/debian-security bullseye-security main contrib non-free" >> /etc/apt/sources.list
```

**效果**：
- ⚡ apt-get update: 从 60s → 5s
- ⚡ apt-get install: 从 180s → 20s

### 2. Python pip 镜像源加速

**已在 Dockerfile.backend 中配置**：
```dockerfile
ARG PYPI_MIRROR=https://mirrors.aliyun.com/pypi/simple/
RUN pip install -i ${PYPI_MIRROR} -r requirements.txt
```

**效果**：
- ⚡ pip install: 从 120s → 15s

### 3. npm 镜像源加速

**已在 Dockerfile.frontend 中配置**：
```dockerfile
ARG NPM_REGISTRY=https://registry.npmmirror.com
RUN npm config set registry ${NPM_REGISTRY}
```

**效果**：
- ⚡ npm install: 从 180s → 30s

## 🚀 额外优化建议

### 优化 1: 使用 Docker 国内镜像源

**配置 Docker Daemon**（在服务器上执行）：

```bash
# 创建或编辑 Docker 配置文件
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com",
    "https://mirror.ccs.tencentyun.com"
  ]
}
EOF

# 重启 Docker
sudo systemctl daemon-reload
sudo systemctl restart docker

# 验证配置
docker info | grep -A 5 "Registry Mirrors"
```

**效果**：
- ⚡ 下载基础镜像速度提升 10-50 倍

### 优化 2: 启用 BuildKit

```bash
# 临时启用（当前会话）
export DOCKER_BUILDKIT=1

# 或者在 /etc/docker/daemon.json 中永久启用
{
  "features": {
    "buildkit": true
  }
}
```

**优势**：
- ✅ 并行构建层
- ✅ 更好的缓存
- ✅ 更快的构建速度

### 优化 3: 使用 Docker Compose 缓存

```bash
# 首次构建（较慢）
./deploy.sh build

# 后续构建（使用缓存，很快）
./deploy.sh build

# 强制重新构建（不使用缓存）
docker-compose build --no-cache
```

## 🔧 逐步构建策略

如果网络仍然不稳定，可以分步构建：

### 方法 1: 单独构建服务

```bash
cd deployment

# 只构建后端
docker-compose build backend

# 只构建前端
docker-compose build frontend

# 只构建 MongoDB（通常很快）
docker-compose pull mongodb
```

### 方法 2: 使用更小的基础镜像

**后端可选：使用 Alpine**

```dockerfile
# 更小的镜像，但兼容性稍差
FROM python:3.11-alpine

# 需要额外安装编译工具
RUN apk add --no-cache gcc musl-dev linux-headers
```

### 方法 3: 预构建本地文件

**前端**：
```bash
# 在本地（Windows）构建
cd frontend
npm run build

# 修改 Dockerfile.frontend 直接复制 dist
FROM nginx:1.25-alpine
COPY dist /usr/share/nginx/html
```

## 🔍 故障排查

### 问题 1: 仍然很慢

**检查 Docker 镜像源**：
```bash
docker info | grep "Registry Mirrors"
```

如果输出为空，说明镜像源未生效。

**解决方案**：
```bash
# 重新配置并重启
sudo systemctl restart docker
```

### 问题 2: apt-get 更新失败

**症状**：
```
E: Failed to fetch https://mirrors.aliyun.com/debian/...
```

**解决方案**：
```bash
# 在 Dockerfile 中添加重试
RUN apt-get update || \
    (sleep 5 && apt-get update) || \
    (sleep 10 && apt-get update)
```

### 问题 3: npm install 超时

**解决方案**：
```dockerfile
# 增加超时时间
RUN npm config set fetch-timeout 600000
RUN npm config set registry https://registry.npmmirror.com
RUN npm install
```

### 问题 4: Docker 构建网络错误

**症状**：
```
ERROR: failed to solve: failed to fetch...
```

**解决方案**：
```bash
# 使用代理（如果有）
docker build --build-arg HTTP_PROXY=http://proxy:port ...

# 或者增加重试
./deploy.sh build || ./deploy.sh build
```

## 💡 最佳实践

### 1. 合理安排构建时间

```bash
# ✅ 推荐：在网络较好的时间段构建
# 例如：晚上或凌晨

# ⚡ 使用 nohup 后台构建
nohup ./deploy.sh build > build.log 2>&1 &

# 查看进度
tail -f build.log
```

### 2. 使用分层缓存

```dockerfile
# ✅ 先复制依赖文件
COPY requirements.txt .
RUN pip install -r requirements.txt

# ✅ 后复制代码文件（经常变动）
COPY . .

# 这样代码修改时不需要重新安装依赖
```

### 3. 清理构建缓存

```bash
# 查看 Docker 占用空间
docker system df

# 清理未使用的镜像
docker image prune -a

# 清理构建缓存
docker builder prune
```

### 4. 监控构建进度

```bash
# 显示详细构建日志
docker-compose build --progress=plain

# 或使用单独的终端查看
docker ps -a
docker logs -f <container_id>
```
