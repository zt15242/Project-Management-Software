# 🔧 Debian 包冲突问题解决

## 问题描述

### 错误信息
```
The following packages have unmet dependencies:
 libatk-bridge2.0-0t64 : Breaks: libatk-bridge2.0-0 (< 2.56.2-1)
 libatk1.0-0t64 : Breaks: libatk1.0-0 (< 2.56.2-1)
 libatspi2.0-0t64 : Breaks: libatspi2.0-0 (< 2.56.2-1)
 libcups2t64 : Breaks: libcups2 (< 2.4.10-3+deb13u2)
E: Unable to correct problems, you have held broken packages.
```

### 根本原因

**Python 3.11-slim 基于 Debian trixie（测试版/不稳定版）**

```bash
# 查看基础镜像的 Debian 版本
docker run python:3.11-slim cat /etc/os-release

# 输出示例：
# ID=debian
# VERSION_ID="13"
# VERSION="13 (trixie)"  ⬅️ 这是新版本
```

**我们配置的是 bullseye（旧稳定版）源**

```dockerfile
# ❌ 错误：覆盖为旧版本源
RUN echo "deb https://mirrors.aliyun.com/debian/ bullseye main..." > /etc/apt/sources.list
                                               ^^^^^^^^
                                             Debian 11（旧版）
```

**结果**：
- 系统需要 trixie 版本的包（包括 t64 变体）
- 但源只提供 bullseye 版本的包
- 导致版本冲突

## ✅ 已解决的所有问题

### 问题 1: chromedriver.exe 跨平台问题 ✅
**症状**: Windows 的 chromedriver.exe 在 Linux 不可用

**解决方案**:
- 更新 `selenium_login.py` 支持跨平台
- 使用 webdriver-manager 自动管理驱动
- Docker 镜像包含 Playwright 作为备选

### 问题 2: Rollup 原生模块缺失 ✅
**症状**: `Error: Cannot find module @rollup/rollup-linux-x64-musl`

**解决方案**:
- 添加编译工具（python3, make, g++）
- 改用 `npm install` 代替 `npm ci --only=production`
- 完整安装 devDependencies

### 问题 3: Docker 构建速度慢 ✅
**症状**: 构建时间 25-50 分钟

**解决方案**:
- 配置 pip 阿里云镜像源
- 配置 npm 淘宝镜像源
- 优化 Docker 层缓存
- 构建时间降至 5-13 分钟

### 问题 4: Debian 包版本冲突 ✅
**症状**: `libatk-bridge2.0-0t64 Breaks libatk-bridge2.0-0`

**解决方案**:
- 不覆盖原有 Debian 源
- 简化依赖列表
- 让 Playwright 自动安装依赖
