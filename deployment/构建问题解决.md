# 🔧 Docker 构建问题解决方案

## 问题：@rollup/rollup-linux-x64-musl 模块缺失

### 错误信息
```
Error: Cannot find module @rollup/rollup-linux-x64-musl
```

### 原因分析
- **Alpine Linux 使用 musl libc**（而非 glibc）
- **Rollup 需要原生模块**，但 npm 可能没有正确安装 Alpine 版本
- **npm ci --only=production** 在某些情况下不会安装构建所需的依赖

---

## ✅ 解决方案

### 已修复的 Dockerfile.frontend

```dockerfile
# 第一阶段：构建应用
FROM node:18-alpine AS builder

WORKDIR /app

ARG NPM_REGISTRY=https://registry.npmmirror.com

# ✅ 关键修复 1: 安装构建依赖
RUN apk add --no-cache python3 make g++

# 配置 npm 镜像源
RUN npm config set registry ${NPM_REGISTRY}

COPY package*.json ./

# ✅ 关键修复 2: 完整安装依赖
RUN npm cache clean --force && \
    rm -rf node_modules package-lock.json && \
    npm install

COPY . .

# 构建生产版本
RUN npm run build

# 第二阶段：Nginx
FROM nginx:1.25-alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

---

## 🔑 关键改动说明

### 1. 添加构建工具
```dockerfile
RUN apk add --no-cache python3 make g++
```

**为什么需要？**
- `python3`: node-gyp 需要 Python
- `make`: 编译原生模块
- `g++`: C++ 编译器

### 2. 改用 npm install
```dockerfile
# 之前（会出错）
RUN npm ci --only=production

# 现在（正确）
RUN npm cache clean --force && \
    rm -rf node_modules package-lock.json && \
    npm install
```

**为什么？**
- `npm ci --only=production` 只安装生产依赖，但构建需要 devDependencies（如 vite）
- 完全重新安装确保所有平台特定的原生模块正确安装

## 🎯 替代方案（如果仍有问题）

### 方案 A: 使用 node:18（Debian 基础）

如果 Alpine 仍有问题，可以切换到 Debian 基础镜像：

```dockerfile
# 第一阶段：构建应用
FROM node:18 AS builder  # 移除 -alpine

WORKDIR /app

ARG NPM_REGISTRY=https://registry.npmmirror.com
RUN npm config set registry ${NPM_REGISTRY}

COPY package*.json ./
RUN npm install

COPY . .
RUN npm run build

# 第二阶段：使用 Nginx（仍可用 Alpine）
FROM nginx:1.25-alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**优势**：
- ✅ 更好的兼容性
- ✅ 更少的原生模块问题

**劣势**：
- ❌ 构建镜像稍大（~200MB vs ~50MB）
- ❌ 构建时间稍长

**注意**：最终镜像大小相同（都是 Nginx Alpine）

### 方案 B: 使用预构建的前端文件

```dockerfile
# 简化版：直接使用构建好的文件
FROM nginx:1.25-alpine

# 直接复制本地构建的 dist 目录
COPY dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**使用方法**：
```bash
# 在本地（Windows）构建前端
cd frontend
npm run build

# 然后部署到服务器
```

**适合场景**：
- 本地网络好，但服务器网络差
- 需要快速部署

## 📝 常见问题

### Q1: 为什么不使用 npm ci？
**A**: `npm ci` 是为 CI/CD 设计的，在某些情况下对原生模块支持不完善。`npm install` 更可靠。

### Q2: 为什么需要 devDependencies？
**A**: Vite 等构建工具在 devDependencies 中，构建阶段必须安装。

### Q3: 可以使用 pnpm 或 yarn 吗？
**A**: 可以，但需要修改 Dockerfile：
```dockerfile
# 使用 pnpm
RUN npm install -g pnpm
RUN pnpm install
RUN pnpm build
```

### Q4: 如何加速构建？
**A**:
1. 使用国内镜像源（已配置）
2. 使用 Docker 构建缓存
3. 考虑使用 BuildKit
